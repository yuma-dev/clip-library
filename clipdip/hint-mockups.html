Rich hint cards A fourth overlay card family — sibling of the clip-saved, notice, and update toasts. Same shell, same two-row height, predefined kinds with built-in white icons.

Everything is the clip-saved card's shell: same background, radius, shadow, entrance (luxein slide + settle), comet border with blurred glow twin, and bottom drain bar. A hint is picked by kind — each kind bundles an accent and a built-in white filled icon (Material Icons filled style, inlined so the overlay stays zero-network at cold start; brand marks like Discord's come from Simple Icons). The backend never chooses colors or art, it just says kind: "warning".

1 — The six predefined kinds

Icons are always white and unglowed; the accent only drives the card's comet, drain, and highlight colors.

Icon sources: Material Icons filled style (Apache 2.0) for the semantic set, Simple Icons (CC0) for brand marks. Both are inlined as raw SVG paths in overlay.html: no font, no CDN, no network at cold start. Every path normalizes to fill: #fff, one rule covers the whole set. Adding a kind = 1 accent line + 1 inlined icon + 1 table row here.

3 — Payload schema

// Rust — src-tauri, sibling of NoticePayload/UpdatePayload
struct HintPayload {
    kind: String,           // "info" | "tip" | "education" |
                            // "warning" | "success" | "discord"
                            // picks accent + icon, overlay-owned
    title: String,          // required, one line, ~40 chars max
    sub: Option<String>,    // body line; [[Ctrl+F10]] renders kbd
                            // chips, **text** renders an .em span
    duration_ms: u32,       // 0 = default 8000
    dismiss_hotkey: String, // cfg.hotkey.rename_clip, e.g. "Ctrl+F10"
    corner: String,         // same corner slug as every toast
    id: String,             // stable id ("discord_popups") so a
                            // hint never double-stacks + history
}

// Example — the Discord popup hint:
{
  "kind": "discord",
  "title": "Discord keeps asking to connect",
  "sub": "Turn off **voice capture** in settings",
  "duration_ms": 10000,
  "dismiss_hotkey": "Ctrl+F10",
  "corner": "bottom_right",
  "id": "discord_popups"
}

// Unknown kind → falls back to "info" so an
// older overlay never renders a broken card.

4 — Behavior spec

aspectbehavior
heightNever taller than the clip-saved card: title row + sub row, same paddings, same gaps. The dismiss tail lives inside the sub row.
entrance/exitReuses luxein / luxeout exactly — hints are corner-anchored like every other card.
cometAlways on, 3.2s lap (slower than saving's 1.4s: a hint idles, it doesn't work). Glow twin synced, opacity 0.6.
drain barAlways armed with the hint's full duration — the card announces its own lifetime, accent-tinted.
dismissThe rename hotkey dismisses (the one chord users already know from the save card, and it's global — reachable in fullscreen games where Escape belongs to the game). Escape also works when the overlay has focus. Backend gates the hotkey exactly like update_toast_active: it acts as dismiss only while a hint is on screen, otherwise it renames as usual.
durationDefault 8s; payload can override (Discord hint uses 10s). Never shorter than 5s — a hint always has more words than "Recording started".
priorityHints never interrupt: a save flow, recording notice, or update toast on screen defers the hint (pending slot, shown when the card frees up, same pattern as pending_notice). A newer hint replaces an older one.
historyEvery hint lands in notification history as kind "hint" with title + sub, so Focus-Assist casualties can be read later.
frequencyHints are rare by contract: each id has its own trigger + cooldown persisted backend-side (the Discord hint: 3 popups / 48h, 7-day cooldown).
